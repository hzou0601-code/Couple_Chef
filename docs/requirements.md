# 产品范围与验收

权威需求为本聊天用户的九部分持续开发指令。交付状态汇总见 ../DELIVERY.html。

- 库存：名称、数量、单位、位置、可选到期日期，新增/编辑/删除/查看，搜索、分类、临期；明确重复、数量不足与空库存。
- 推荐：规则与结构化菜谱优先；不补充只推荐库存足够菜品，展示默认调味料；允许补充展示已有、缺失和缺口数量，汇总购物清单。两种模式均提供理由、用料、份量、步骤。不跨维度直接比较单位，不编造库存，推荐不足说明原因。
- 做饭：仅用户确认完成后扣库存；事务一致、重复确认幂等，库存变化后重新检查。
- 前端：微信小程序原生兼容布局与交互，统一设计变量、复用组件和导航，各主要页面加载/空/错/成功。
- 架构与质量：前端 API → 后端 → 独立数据库；版本迁移；输入校验、统一错误、配置示例；锁文件、静态/类型/格式检查、核心/集成/E2E测试、前后端构建、迁移恢复与远程 CI。
- MVP 完成条件：以上全部有验证证据，必要检查通过；未验证不打勾。完成后停止新增功能，无新问题不修改。
- 未授权生产发布、正式提审、付费AI。测试部署仅限已有配置和授权。
